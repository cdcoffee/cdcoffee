# 算力与工厂物联网

> 让本地算力与设备感知成为产线的基础设施，而不是每次临时搭环境。

## 何时用

- 要规划本地推理 / 生成任务的算力调度。
- 产线设备、环境传感器的数据要接入统一视图。
- 需要判断「这一步该本地跑还是该上云」。

## 输入

- 任务类型、并发量级（只描述量级，不写经营数值）。
- 可用设备与网络约束。
- 数据敏感度分级：哪些数据不允许离开本机。

## 输出

- 算力分层方案：本地常驻 / 按需拉起 / 外部调用，各管什么。
- 设备接入清单：点位、字段、采集频率、异常判定。
- 运行手册：启动、健康检查、显存与队列排障。

## 做法

1. **先分级**：按数据敏感度决定能不能出本机，再谈性能。
2. **定常驻边界**：只让高频、稳定的能力常驻，其余按需拉起。
3. **统一点位命名**：设备、点位、字段三处命名一次定死。
4. **设健康检查**：启动后跑一轮冒烟测试，失败即停不留半状态。
5. **写排障手册**：把踩过的坑按「症状 → 根因 → 解法」记录。

## 验收

- [ ] 相同任务重复跑，结果与环境一致。
- [ ] 敏感数据全程未离开本机，有可核对的路径说明。
- [ ] 服务异常时能一键释放资源并恢复。
- [ ] 方案不含设备清单明细、内网地址与账号信息。

## 不做什么

- 不为了省事把敏感序列或原始记录传到外部服务。
- 不把单点演示当成已部署的基础设施对外陈述。
- 不写内网地址、端口映射、设备序列号与凭据。
- 不在没有回滚方案的情况下改动生产环境配置。

# 技能沉淀与同步

> 干得好就存成技能：能复用、能交接、能回滚，而不是留在一次对话里。

## 何时用

- 一个方法被用了不止一次，且换个人照着也能做。
- 岗位试岗合格，要把做法固化下来。
- 换机器、交班或需要回溯「这个方法什么时候改过」。

## 输入

- 本次做法：步骤、判断标准、验收条件、失败记录。
- 三条沉淀线：复用次数、可交接性、是否有验收。
- 目标资产库位置与同步规则。

## 输出

- 一张技能卡或一份完整技能：含触发词、输入、输出、验收、边界。
- 一次带说明的提交记录（写清哪个技能、什么变化）。
- 变更记录里的一笔，便于回溯。

## 做法

1. **过三条线**：复用、可交接、有验收，缺一条先不沉淀。
2. **写方法不写数据**：只保留可迁移的骨架，删掉具体数字、名称、路径。
3. **脱敏**：推前跑密钥扫描与脱敏自检，任一不过即中止。
4. **提交**：说明写清「什么技能 / 什么变化」，不写笼统的更新。
5. **双写**：资产库与归档盘各一份，本体与副本分离。

## 验收

- [ ] 新同事读卡即可复现，不需要追问上下文。
- [ ] 扫描通过，且卡内无任何凭据或涉密内容。
- [ ] 提交说明可追溯，工作树干净。
- [ ] 变更记录留了一笔。

## 不做什么

- 不把一次性的临时提示词当成技能。
- 不把 token 写进远端地址、配置、日志或对话。
- 不在扫描失败时强行提交或绕过检查。
- 不擅自把内部完整副本对外分享；对外只给脱敏简洁卡。

# 共同记忆与口径闸门

> 让所有岗位读同一份上下文，并对「哪些数字能对外」设一道闸门。

## 何时用

- 多个岗位并行干活，却各写各的背景，说法开始打架。
- 要对外出材料，需要确认某个数字、案例或主体名称能不能用。
- 新岗位上岗、老项目复盘、知识库定期迭代。

## 输入

- 项目与任务底稿（共同上下文，标注待校订处）。
- 人机协作协议（目录规则、复述闸门、禁止人工搬运）。
- 权威口径表（裁决过的说法，含生效范围与使用限制）。

## 输出

- 一份所有岗位共读的上下文入口。
- 一版可迭代的知识库：资产台账、主题摘要、变更记录。
- 一份口径裁决记录：冲突是什么、最终用哪个、适用范围。

## 做法

1. **只读扫描**：先盘点已有成果文件，不改动任何原始资料。
2. **分类建索引**：按主题归类，文件名优先、目录兜底，避免整棵目录被归成一类。
3. **抽取正文**：不只对文件清单做索引，把代表性文档内容读进摘要卡。
4. **设闸门**：冲突口径写入权威表；未裁决的一律标注「引用前须复核」。
5. **可迭代**：脚本可重跑；每次裁决、每次重扫都在变更记录里留一笔。

## 验收

- [ ] 重跑脚本后，摘要卡能自动反映最新状态。
- [ ] 每个对外数字都能追溯到权威口径或原始表。
- [ ] 未裁决口径在成果里表现为留白或明确标注，不自行取值。
- [ ] 原始资料文件零改动。

## 不做什么

- 不把产值口径与利润口径混用、相加或并列不标注。
- 不把宣传说法直接写进技术文件。
- 不为了「清理干净」去删改原始成果文件；红线只约束引用。
- 不在知识库里放账号、密钥、授权码或本机绝对路径。
